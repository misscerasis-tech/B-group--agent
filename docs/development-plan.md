# 开发计划

## 总体策略

开发采用“稳定主线 + 阶段分支 + 可回滚 Tag”的方式推进。

- `main` 只保存可运行、可测试、可演示版本。
- 每个阶段从 `main` 创建独立分支。
- 阶段完成后运行测试、更新文档和 `CHANGELOG.md`，再提交。
- 确认可运行后再合并回 `main` 并打 Tag。

## 阶段 0：仓库初始化

建议 Tag：`v0.0.1-initial`

目标：

- 创建独立项目目录。
- 初始化 Git 仓库和 `main` 分支。
- 创建基础文件和规划文档。
- 不启动产品功能开发。

验收：

- 仓库是独立 Git 仓库。
- `main` 分支存在。
- 基础文件齐全。
- 初始化 commit 和 Tag 存在。

## 阶段 1：Foundation 最小系统骨架

建议分支：`feature/phase-1-foundation`

建议 Tag：`v0.1.0-foundation`

目标：

- 搭建 Next.js + TypeScript Web 应用。
- 建立中文基础界面框架。
- 建立数据库迁移体系。
- 建立 Workspace / User / Project / Product 的最小数据模型。
- 建立测试、格式化和基础 CI 约束。
- 提供本地启动说明。

不做：

- 不接入真实飞书。
- 不接入真实 AI 内容生成。
- 不做完整素材生成。

最小可测试范围：

- 可以本地启动 Web。
- 可以看到中文首页或工作台。
- 可以创建 Workspace、项目和产品的最小记录。
- 数据库结构通过迁移文件创建。
- 基础测试可以运行并通过。

## 阶段 2：Product Brain 产品与策略大脑

建议分支：`feature/phase-2-product-brain`

建议 Tag：`v0.2.0-product-brain`

目标：

- 支持产品画像、卖点、目标市场、客群和渠道信息。
- 支持中文自然语言输入增长目标。
- 生成结构化策略草稿。
- 支持人工校准并保存正式策略版本。

验收：

- 一个产品可以生成并保存策略草稿。
- 正式策略有版本记录。
- AI 输出和人工修改可以追踪。

## 阶段 3：Content Pack 内容素材包

建议分支：`feature/phase-3-content-pack`

建议 Tag：`v0.3.0-content-pack`

目标：

- 根据策略生成内容计划。
- 生成多平台文案草稿。
- 建立素材包结构。
- 支持打包下载。

验收：

- 一个产品可以生成一个内容素材包。
- 素材包可以被审核、下载和追踪状态。

## 阶段 4：Poster Composer 模板化海报合成

建议分支：`feature/phase-4-poster-composer`

建议 Tag：`v0.4.0-poster-composer`

目标：

- 上传真实产品图。
- 建立可配置海报模板。
- 合成带产品图、文案、价格和卖点的海报。
- 按平台规格导出。

验收：

- 可以基于真实产品图生成模板化海报。
- 导出结果可下载。

## 阶段 5：Review, Reminder, Recap 审核提醒与复盘

建议分支：`feature/phase-5-review-reminder-recap`

建议 Tag：`v0.5.0-review-recap`

目标：

- 审核任务流。
- 定期提醒。
- 内容表现数据手动录入或导入。
- 复盘报告和下一轮建议。

验收：

- 素材包可以进入审核。
- 可以设置提醒。
- 可以记录数据并生成复盘。

## 阶段 6：Feishu Connector 飞书可插拔集成

建议分支：`feature/phase-6-feishu-connector`

建议 Tag：`v0.6.0-feishu-connector`

目标：

- Workspace 级连接飞书。
- 测试连接。
- 选择通知群和沉淀位置。
- 发送任务、提醒和审核通知。
- 支持停用、换绑和迁移记录。

验收：

- 未连接飞书时核心业务仍可运行。
- 连接飞书后可以发送通知。
- 可以更换飞书组织并保留迁移记录。

## 阶段 7：Demo Version

建议分支：`feature/phase-7-demo`

建议 Tag：`v1.0.0-demo`

目标：

- 打磨完整演示路径。
- 完成部署说明。
- 准备演示数据。
- 完成安全检查和回滚演练。

验收：

- 新品品牌团队可以完成从产品输入到策略、素材包、审核、下载、复盘的闭环演示。

## 每阶段人工操作清单

- 提供或确认业务样例产品。
- 确认每阶段验收口径。
- 如需远程仓库，创建 GitHub 空仓库并提供地址。
- 如需 AI、飞书、对象存储或部署平台，提供相应账号授权或环境变量。
- 危险数据库迁移前确认备份和回滚方案。
